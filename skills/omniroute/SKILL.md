# Работа через OmniRoute

## Когда брать

- Нужна модель, которой нет среди подключённых в opencode: OmniRoute
  собирает провайдеров за одним адресом и отдаёт их как один провайдер.
- Нужны бесплатные модели: часть провайдеров работает без ключа вообще,
  и программа подключает их сама.
- Нужен автоподбор модели и запасной путь, когда провайдер отказал
  (`auto` — модель, которую советует сам OmniRoute).
- Нужно понять, сколько стоит работа: у шлюза есть отчёт по расходам.

## Когда не брать

- **Нужна конкретная модель с твоим ключом.** Если ключ уже вписан в
  opencode напрямую, шлюз тут лишний посредник. Рабочая замена — обычный
  провайдер в настройках opencode.
- **Нужна работа без запущенного шлюза.** OmniRoute — отдельная программа
  на этой машине: пока она не запущена, инструменты отвечают «fetch
  failed». Замена — встроенные модели opencode.
- **Мост не развёрнут или не отвечает.** Тогда говори прямо и предлагай
  шаги: вкладка opencode, блок «6. Серверы MCP», строка OmniRoute —
  «Развернуть», «Запустить», «Показать статус». Панель и API живут на
  `http://127.0.0.1:20128`. После включения в opencode нужен перезапуск.

## Как устроена связь

```
opencode ──► omniroute_bridge_launcher.py ──► omniroute --mcp (stdio)
             ставит DATA_DIR рядом с                    │
             настройками opencode, PORT,                │ инструменты MCP
             OMNIROUTE_SERVER_HOST                      ▼
                                              сервер OmniRoute :20128
                                              (панель + API /v1)
                                                        │
                                    бесплатные провайдеры без ключа —
                                    подключены программой; ключи от
                                    сервисов человек вписывает в панели
```

Две части у одного моста:

- **MCP-сервер** (`omniroute --mcp`) — его opencode запускает через
  лаунчер. 110 инструментов: здоровье, комбо, модели, провайдеры, ключи,
  расходы.
- **Сервер шлюза** (`omniroute serve`) — панель и OpenAI-совместимый API
  на `http://127.0.0.1:20128/v1`. Через него работают модели: запись
  провайдера `omniroute` в настройках opencode смотрит сюда.

Без второго первое бесполезно: инструменты MCP ходят на тот же API.

## Подключение после запуска

```
1. Показать статус      — развёрнут ли, отвечает ли API, какая версия
2. Запустить            — если API молчит
3. Настроить автоматически — бесплатные провайдеры + запись в opencode
4. Перезапустить        — если зависло или список провайдеров поменялся
```

Что делает «Настроить автоматически», по шагам:

1. ставит пакет из npm в папку моста, если его нет;
2. поднимает сервер и **ждёт ответа** `GET /api/health` — «ok»;
3. читает каталог провайдеров заново и подключает бесплатных, которым
   ключ не нужен;
4. вписывает провайдера `omniroute` в `opencode.jsonc` и включает
   MCP-сервер;
5. говорит перезапустить opencode.

Порядок не переставлять: сначала живая проверка, потом запись. Если API
не ответил, в настройки opencode не попадает ничего.

## Бесплатные провайдеры

Список читается заново при **каждом** развёртывании и **каждом**
перезапуске, поэтому изменившийся каталог новой версии подхватывается
сам: чего нет — добавится, что уже стоит — не тронется.

- **Без ключа (категория `noauth`)** — программа подключает сама командой
  `omniroute providers add <id> --allow-no-credential --yes`. Таких в
  каталоге 3.8.51 шесть: `opencode`, `duckduckgo-web`,
  `cloudflare-playground`, `veoaifree-web`, `uncloseai`, `aihorde`.
- **С ключом сервиса** — программа их не подключает и ключи не выдумывает.
  Их вписывает человек в панели OmniRoute (вкладка Providers). На 07.10.2026
  бесплатных с ключом было 143 из 358 — говорить «подключены все» нельзя.

Проверить, что подключено, можно и самому — командами моста из корня
базы (они зовут тот же код, что кнопки окна):

```
python tools/dbapp/omniroute.py status   — развёрнут ли, отвечает ли API,
                                           какая версия, сколько провайдеров
python tools/dbapp/omniroute.py sync     — заново прочитать каталог
                                           и подключить бесплатных без ключа
python tools/dbapp/omniroute.py start    — поднять сервер
python tools/dbapp/omniroute.py restart  — перезапустить и проверить
```

## Перезапуск, если мост упал

Признаки: `omniroute_get_health` отвечает «fetch failed» или пустая
страница панели.

```
1. python tools/dbapp/omniroute.py status    — «API не отвечает» значит,
                                               что сервер не поднят
2. python tools/dbapp/omniroute.py restart   — остановка, запуск, живой
                                               запрос и заново подключение
                                               бесплатных провайдеров
3. python tools/dbapp/omniroute.py status    — убедиться, что ответ вернулся
```

То же самое человек делает кнопками «Показать статус» и «Перезапустить»
в окне программы (вкладка opencode, блок «6. Серверы MCP», строка
OmniRoute) — команды и кнопки зовут один код.

Если перезапуск не помог — не выдавай зелёную отметку. Смотри журнал в
папке данных (`omniroute-data` рядом с настройками opencode) и скажи
человеку, что именно написано, без догадок.

## Частые ошибки

| Что делают неправильно | Как правильно |
|---|---|
| Считают «процесс запущен» за «мост работает» | Признак работы — ответ API `{"status":"ok"}`, а не запущенный процесс |
| Говорят «все бесплатные провайдеры подключены» | Без ключа — да, их шесть. Остальные 143 требуют ключ сервиса |
| Вписывают ключи провайдеров в `opencode.jsonc` | Ключи живут в папке данных OmniRoute (`omniroute-data`) и вписываются в панели |
| Копируют ключи из панели в чат или в журнал | Никогда. Ни при какой отладке |
| Работают сразу после включения в opencode | Нужен перезапуск opencode: он поднимает серверы при чтении настроек |
| Переставляют шаги: сначала запись, потом проверка | Сначала живая проверка, потом запись. Иначе в списке неработающий сервер |

## Осторожно

- **Ключи чужих сервисов.** Папка `omniroute-data` рядом с настройками
  opencode хранит ключи провайдеров и ключ шифрования хранилища. Это
  секреты этой машины: не переноси их в репозиторий, в переписку и в
  логи.
- **Расходы.** Часть провайдеров платные. Прежде чем отправлять много,
  посмотри отчёт по расходам (`omniroute_cost_report`) и лимиты ключей.
- **Ответ уходит в чужой сервис.** Запросы идут провайдеру, которого
  выбрал шлюз. Приватный код и секреты в подсказку не вставлять.
- **Панель слушает только эту машину.** Адрес — `127.0.0.1:20128`: с
  других устройств она недоступна, и это сделано нарочно.
