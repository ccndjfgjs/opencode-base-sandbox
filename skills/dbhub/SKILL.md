# Работа через DBHub

## Когда брать

- Нужно посмотреть, какие таблицы и колонки есть в базе.
- Нужно выполнить запрос и вернуть результат человеку: `SELECT`, подсчёт,
  группировка, выборка по условию.
- Нужно разобрать схему перед тем, как писать запрос или разбираться в
  чужой базе.

## Когда не брать

- **Нужно изменить данные или схему** (`INSERT`, `UPDATE`, `DELETE`,
  `CREATE`, `ALTER`). Мост по умолчанию в режиме «только чтение» и такие
  запросы отклоняет — это не поломка. Изменить режим может только человек
  в окне программы, при добавлении подключения.
- **Нужна вся таблица целиком.** В ответе ограничено число строк
  (по умолчанию 1000). Для большой выгрузки нужен обычный клиент к базе
  или `pg_dump`/`mysqldump` — скажи об этом прямо.
- **Мост не настроен.** Тогда говори прямо и предлагай шаги: вкладка
  opencode, блок «6. Серверы MCP», строка DBHub — сначала «Добавить
  подключение», потом «Проверить соединение» или «Настроить
  автоматически». После включения нужен перезапуск opencode.

## Как устроена связь

```
opencode ──► dbhub_bridge_launcher.py ──► DBHub (npx) ──► база данных
             берёт пароль из                        PostgreSQL, MySQL,
             mcp-dbhub-<имя>-password.txt           MariaDB, SQL Server,
                                                    Oracle, SQLite
```

Сам сервер ставить не нужно: npx скачивает пакет `@bytebase/dbhub` при
первом запуске и обновляет его сам. Наша часть — лаунчер, который кладёт
пароль в окружение процесса до старта, и файл подключений
`mcp-dbhub.toml` рядом с настройками opencode.

Инструментов два:

| Инструмент | Для чего |
|---|---|
| `search_objects` | поиск по схеме. Обязателен `object_type`: `schema`, `table`, `view`, `column`, `procedure`, `function`, `index` |
| `execute_sql` | запрос к базе. В режиме «только чтение» проходят `select`, `with`, `explain`, `pragma`, изменение данных отклоняется с `READONLY_VIOLATION` |

## Порядок действий

```
1. search_objects(object_type="table")        — какие таблицы есть
2. search_objects(object_type="column", ...)  — колонки нужной таблицы
3. execute_sql                                 — точечный SELECT
4. показать строки, которые вернул сервер      — а не пересказ по памяти
```

- Спрашивай только нужные колонки и добавляй `LIMIT`: `SELECT a, b ...
  LIMIT 20`, а не `SELECT *`.
- «Готово» — только после ответа с данными. Пустой ответ — тоже ответ:
  так и скажи («ничего не найдено») и покажи, что именно спрашивал.

## Частые ошибки

| Что делают неправильно | Как правильно |
|---|---|
| `SELECT *` по большой таблице | Перечислить колонки и ограничить строки |
| Изменяют данные и удивляются отказу | Режим «только чтение» включён по умолчанию; менять его может только человек в окне |
| Считают «сервер вписан» за «база отвечает» | Связь показывает живая проверка, а не запись в настройках |
| Пересказывают результат словами | Показывают строки, которые вернул сервер |
| Работают сразу после включения | Нужен перезапуск opencode: он поднимает серверы при чтении настроек |

## Осторожно

- **Пароль базы не в конфиге.** Он лежит отдельным файлом рядом с
  настройками (`mcp-dbhub-<имя>-password.txt`), а в строке подключения
  стоит ссылка на переменную окружения. Не переноси пароль в
  `opencode.jsonc` и не вставляй его в чат.
- **Данные в базе — чужие.** Даже `SELECT` может вернуть персональные
  данные. Не копируй в переписку больше, чем нужно для ответа.
- **Тяжёлый запрос может уронить чужую работу.** Перед запросом без
  ограничения подумай о нагрузке на базу, особенно если она боевая.
