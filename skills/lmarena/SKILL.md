# Работа через мост LMArena

## Когда брать

- Нужна модель, которой нет среди подключённых в opencode, а ключа к ней
  нет: мост отдаёт модели площадки LMArena обычным OpenAI-совместимым API,
  и они становятся провайдером `lmarena` в настройках opencode.
- Нужно сравнить ответы нескольких площадочных моделей на один вопрос.
- Нужно спросить площадочную модель про текст, который **не жалко** отдать
  на публичную площадку.

## Когда не брать

- **Приватный код, чужие данные, ключи, переписка.** Запросы уходят на
  веб-сервис Arena и на этой площадке могут использоваться для оценки и
  публикации результатов. Это не официальный API, а работа через сайт:
  несоответствие условиям сервиса возможно, и доступ может отвалиться без
  предупреждения. Для приватного — встроенные модели opencode.
- **Нужны стелс-модели.** Этот форк их не отдаёт: список их не показывает,
  а запрос к ним отвечает 403 «You do not have access to stealth models».
  Обещать их нельзя.
- **Мост не запущен или токена арены нет.** Список моделей пуст, живая
  проверка отказывает. Скажи об этом прямо и предложи шаги: вкладка
  opencode, блок «6. Серверы MCP», строка LMArena — «Развернуть», «Обновить
  токен», «Запустить», «Показать статус».
- **Нужна стабильность и предсказуемость.** У площадки лимиты и защита от
  роботов (reCAPTCHA, Cloudflare), поэтому отказы и задержки ожидаемы.

## Как устроена связь

```
opencode ──► lmarena_bridge_launcher.py ──► HTTP API моста :8000/api/v1
             наш stdio-сервер MCP:                    │
             lmarena_status, lmarena_models,          │
             lmarena_chat                             ▼
                                          LMArenaBridge (python -m src.main)
                                          панель /dashboard, API /api/v1
                                                      │
                                          запросы уходят на arena.ai
                                          с токеном arena-auth-prod-v1
```

Три части у одного моста:

- **Мост-программа** (форк LMArenaBridge, лежит кодом в
  `tools/thirdparty/lmarena`) — поднимается кнопкой «Запустить» или самим
  лаунчером, если он не отвечает.
- **Наш MCP-слой** (лаунчер) — у форка MCP нет, поэтому его написали мы:
  три инструмента поверх HTTP API моста. Признак работы — ответ API
  `GET /api/v1/health` со статусом `healthy` или `degraded`, а не
  «процесс запущен».
- **Токен арены** — файл `mcp-lmarena-token.txt` рядом с настройками
  opencode; оттуда он уезжает в `config.json` моста (папка
  `lmarena-data`). В настройки opencode токен не попадает никогда.

Статусы здоровья: `healthy` — мост получил с арены куку и список моделей;
`degraded` — сервер жив, но токена или моделей ещё нет. `degraded` — это
работающий мост без токена, а не успех.

## Подключение после запуска

```
1. Показать статус      — развёрнут ли, отвечает ли мост, есть ли токен,
                          сколько моделей
2. Запустить            — если мост молчит (переносит токен в мост)
3. Модели: есть?        — нет моделей → токен протух, «Обновить токен»
4. Настроить автоматически — живой ответ модели, затем провайдер с моделями
                          арены и MCP-сервер в настройки opencode
5. Перезапустить        — если зависло или список моделей изменился
```

Что делает «Настроить автоматически», по шагам:

1. проверяет, что мост развёрнут, и поднимает его (переносит свежий токен);
2. **спрашивает у модели настоящий ответ** — живая проверка, а не взгляд
   на файлы;
3. берёт у моста список моделей и вписывает провайдера `lmarena` в
   `opencode.jsonc` тем же механизмом, что Ollama, LM Studio и OmniRoute;
4. включает MCP-сервер (тот же блок, что у остальных мостов);
5. говорит перезапустить opencode.

Порядок не переставлять: сначала живая проверка, потом запись. Нет токена,
нет ответа модели, арена недоступна — в настройки opencode не попадает
ничего.

Команды моста из корня базы (зовут тот же код, что кнопки окна):

```
python tools/dbapp/lmarena.py status            — что развёрнуто и отвечает ли
python tools/dbapp/lmarena.py start             — поднять мост (переносит токен)
python tools/dbapp/lmarena.py restart           — перезапустить и проверить
python tools/dbapp/lmarena.py models            — список моделей моста
python tools/dbapp/lmarena.py sync              — заново вписать модели в провайдера
python tools/dbapp/lmarena.py token             — есть ли токен (значение не показывает)
```

## Токен: обновить, если протух

Признаки: `status` говорит «токена нет» или «моделей нет», `models` пуст,
`lmarena_chat` отвечает отказом про токен или 403.

```
1. Человек берёт свежую куку arena-auth-prod-v1 на сайте арены:
   отправить сообщение, F12 → Application → Cookies → arena-auth-prod-v1
   (значение начинается с base64-).
2. Кнопка «Обновить токен» — вставить значение. Оно ложится файлом рядом
   с настройками opencode и в репозиторий не попадает.
3. Кнопка «Перезапустить» (окно само предложит) — мост перечитает токен
   и заново возьмёт список моделей с арены.
4. «Показать статус» — должно стать «токен есть» и «моделей: N».
```

Сам токен не показывай и не пересказывай: его место — только файл рядом с
настройками. Токен, вставленный в чат или в лог, считается утёкшим.

## Перезапуск, если мост упал

```
1. python tools/dbapp/lmarena.py status    — «API не отвечает» значит, мост
                                             не поднят или завис
2. python tools/dbapp/lmarena.py restart   — остановка, запуск, ожидание
                                             ответа API, перенос токена
3. python tools/dbapp/lmarena.py status    — убедиться, что ответ вернулся
```

То же самое человек делает кнопками «Показать статус» и «Перезапустить» в
окне программы — команды и кнопки зовут один код.

Если перезапуск не помог — не выдавай зелёную отметку. Журнал моста лежит
в папке `lmarena-data` рядом с настройками opencode (`bridge.log`), там же
`config.json` и `models.json`. Скажи человеку, что именно написано, без
догадок. Частые причины: протух токен, арена закрыла доступ, нет сети.

## Частые ошибки

| Что делают неправильно | Как правильно |
|---|---|
| Считают «процесс запущен» за «мост работает» | Признак работы — ответ `GET /api/v1/health`, а не запущенный процесс |
| Говорят про стелс-модели | Этот форк их не отдаёт: 403 и пустая строка в списке |
| Вписывают токен арены в `opencode.jsonc` | Токен живёт файлом рядом с настройками и в `config.json` моста |
| Подставляют в провайдера «любой» ключ | Без ключа мост берёт свой первый ключ; подставленный чужой даёт 401 |
| Выдумывают имена моделей для провайдера | Список берётся у живого моста (`models`/`sync`) |
| Работают сразу после включения в opencode | Нужен перезапуск opencode: он читает настройки при запуске |
| Переставляют шаги: сначала запись, потом проверка | Сначала ответ модели, потом запись. Иначе в списке неработающий мост |

## Осторожно

- **Условия сервиса.** Мост работает через веб-сайт Arena, а не через
  официальный API. Такое использование может не соответствовать условиям
  сервиса; доступ может перестать работать без предупреждения. Мост
  выключен по умолчанию и включается только после предупреждений.
- **Публичная площадка.** Запросы уходят на арену и могут использоваться
  для оценки и публикации. Приватный код и секреты — никогда.
- **Лимиты и защита.** Бесплатный доступ ограничен, на площадке стоят
  проверки на робота; нестабильность ожидаема. Не запускай сотни запросов
  подряд.
- **Панель моста слушает все интерфейсы.** Так написано в коде форка
  (`host="0.0.0.0"`), а пароль панели по умолчанию `admin`. На общей сети
  пароль надо сменить в панели или мост не запускать. Программа об этом
  предупреждает.
- **Токен — секрет этой машины.** Он лежит файлом рядом с настройками
  opencode, в репозиторий не попадает, в логи и в чат не выводится.
