# Второй ревьюер: Qwen Code

## Когда брать

- Основной агент закончил задачу — и нужен **взгляд второй модели** на
  изменения: ошибки, крайние случаи, безопасность, сомнительные решения.
- Работа идёт в git-репозитории: ревьюеру нужен `git diff` (рабочее дерево
  или разница с веткой — `--base main`).
- Человек хочет **второе мнение перед сдачей**: перед коммитом, PR или
  демонстрацией.

## Когда не брать

- **Нет git-репозитория.** Ревьюер берёт `git diff`: без репозитория
  сравнивать нечего. Скажи прямо и предложи `git init` либо обычную
  проверку кода.
- **Ревьюер не настроен.** Не развёрнут Qwen Code, нет Node.js 22+, не
  выбрана модель или галочка снята. Пусть человек откроет вкладку opencode,
  отметит галочку «Qwen Code — второй ревьюер» и выберет модель. **Не
  выдумывай замечания от имени ревьюера.**
- **Провайдер не в формате OpenAI.** Qwen Code говорит с провайдером на
  языке OpenAI. Если у провайдера из opencode не OpenAI-совместимый
  интерфейс, программа честно скажет, что он не подходит: подставлять
  наугад другой адрес или модель нельзя.
- **Задача про экономию.** Это наоборот: каждая проверка тратит токены,
  а спор — по запросу на раунд. Если лимиты на пределе, ревьюер не нужен.

## Как это устроено

```
основной агент ──► скилл берёт git diff проекта
                       │
                       ▼
        Qwen Code (headless: `qwen -p … --approval-mode plan`)
          режим «только чтение»: файлы не правит, команд не запускает
                       │
                       ▼
   замечания возвращаются основному агенту и показываются человеку
   <настройки opencode>/qwen-review-data/ — наш дом: настройки,
     журнал проверок и ход спора (раунды, доводы, расход токенов)
```

Модель ревьюера выбирается из провайдеров, **уже подключённых в
opencode** (включая OmniRoute и мост LMArena, если они включены).
Программа пишет выбор в настройки Qwen Code в своём доме (`QWEN_HOME`
внутри `qwen-review-data`), поэтому личный `~/.qwen` пользователя не
трогается. Ключ провайдера в настройки не записывается: он уезжает
в окружение процесса при запуске и в окно и журналы не попадает.

## Как запускать

**Из окна программы** (обычный путь): вкладка opencode, галочка
`qwen-review` → провайдер и модель → «Сохранить выбор» → «Проверить
изменения…» (папка проекта и база сравнения). Кнопки «Проверить
окружение» и «Развернуть Qwen Code» — для подготовки.

**Командой** (то же самое; так же зовёт агент `@retsenzent-qwen`):

```
python tools/dbapp/qwen_review.py status                  # что готово
python tools/dbapp/qwen_review.py providers               # провайдеры и модели
python tools/dbapp/qwen_review.py choose <провайдер> <модель>
python tools/dbapp/qwen_review.py deploy                  # развернуть Qwen Code
python tools/dbapp/qwen_review.py review <папка> [--base main]
python tools/dbapp/qwen_review.py review <папка> --reply "возражение" --rounds 3
python tools/dbapp/qwen_review.py forget                  # забыть ход спора
```

Флаги самого Qwen Code — из его документации: `-p/--prompt` (headless),
`--approval-mode plan` (только чтение), `-o json` (ответ с расходом
токенов), `--openai-base-url`/`--auth-type openai` (свой адрес API).
Наш модуль задаёт адрес и ключ окружением, а не аргументами.

## Правила

- **Ревьюер не правит код.** У него `--approval-mode plan`, у агента
  `@retsenzent-qwen` — `edit: deny`, а из команд разрешена только одна:
  `python tools/dbapp/qwen_review.py …`. Замечания — словами, правки —
  за основным агентом и человеком.
- **Спор — не победа.** Отдельный режим, по умолчанию выключен, не больше
  трёх раундов (предел 5). За пределом раундов программа не решает сама:
  она показывает человеку оба довода и спорный фрагмент, и решает человек.
  Расход токенов виден по раундам.
- **Код уходит провайдеру.** Если выбран мост LMArena — это публичная
  площадка: приватный код и секреты туда не отправляют, окно говорит об
  этом прямо.
- **Ключ — не для показа.** Ключ провайдера не выводить ни в ответ, ни в
  журнал, ни в файлы репозитория.
- **Обе модели могут ошибаться.** Спор двух моделей не доказывает правоту
  ни одной. Решение — за человеком и за тестами. Модель ревьюера лучше
  выбирать другую, чем у основного агента.
- **Не MCP.** Это консольный агент, а не сервер: в `mcp-registry.json` его
  нет и быть не должно.

## Частые ошибки

- «Ревьюер не ответил» при пустом списке провайдеров → в opencode не
  подключён ни один OpenAI-совместимый провайдер. Скажи это прямо.
- Проверка без `--base` показывает только незакоммиченные изменения
  (`git diff`), а не всю ветку: для работы поверх основной ветки
  указывай `--base main`.
- Ревью прошло, а ошибки остались → ревьюер смотрит только изменения:
  то, что лежит вне diff, он не видит.
- Спор без первого ревью → раунды начинаются с обычной проверки; кнопка
  «Возразить и продолжить…» до первого ревью не работает.
