# Работа через браузер

## Когда брать

Нужен настоящий браузер, а не запрос по сети: сайт рисуется на JavaScript,
страница закрыта входом, надо нажать кнопку, заполнить форму, снять
скриншот или пройти по вкладкам. Тогда мост даёт то, чего не даёт
`fetch`: разобранную страницу с именами элементов, по которым можно
щёлкать.

## Когда не брать

- Нужен один файл или ответ API — хватит обычного запроса: браузер тут
  дороже и медленнее.
- Задача про свой браузер с личными вкладками и входами — по умолчанию
  мост водит **отдельный** профиль, твоих сессий он не видит. Режим «мои
  сессии» включается человеком явно и требует расширения Playwright.
- Мост не настроен — скажи прямо и не делай вид, что открыл страницу.

Рабочая замена без моста: `curl` для страниц без JavaScript, скрипт на
Python с `requests` для API, `playwright` из командной строки, если он
стоит у человека.

## Если мост не настроен

В окне программы: вкладка **opencode**, блок **«6. Серверы MCP»**, строка
**Браузеры**:

1. **«Выбрать браузер»** — Chrome, Edge, Яндекс.Браузер или Firefox;
   профиль и показывать ли окно.
2. **«Проверить браузер»** — программа откроет страницу и прочитает
   заголовок.
3. **«Настроить автоматически»** — только после удачной проверки впишет
   сервер в настройки opencode.

После этого — перезапуск opencode. Подробности — в `инструкции/МCP-серверы.md`.

## Что важно знать про браузеры

| Браузер | Как запускается | Ограничение |
| --- | --- | --- |
| Chrome | по каналу `--browser chrome` | нужен установленный Chrome |
| Edge | по каналу `--browser msedge` | есть в Windows из коробки |
| Яндекс.Браузер | по пути к `browser.exe` | путь указывает человек, канала у Playwright нет |
| Firefox | своя сборка Playwright | **твой Firefox не подойдёт**: Playwright водит только свою сборку, около 90 МБ |

Режимы профиля: **отдельный** (по умолчанию, свои вкладки), **без
сохранения на диске** и **«мои сессии»** — только Chrome и Edge, только с
расширением Playwright, которое человек ставит сам.

## Порядок работы

Работа идёт циклом, и порядок шагов нарушать нельзя:

```
1. открыть страницу       — browser_navigate
2. посмотреть разбор      — browser_snapshot (имена элементов и роли)
3. действовать            — click / type / fill_form по имени из разбора
4. проверить результат    — снова snapshot или browser_evaluate
5. только теперь «готово»
```

**«Готово» без проверки после последней правки — не «готово».** Нажатие
может не сработать, форма — не отправиться, а страница — показать ошибку
вместо результата. Скилл `verification-before-completion` здесь действует
в полную силу.

Частая ошибка: действовать по памяти о странице вместо свежего разбора.
Страница меняется между шагами, и имена элементов вместе с ней.

## Чего не делать

- Не отправлять через браузер секреты, пароли и приватный код: если это
  чужой сайт, текст уходит наружу.
- Не входить в чужие аккаунты и не обходить проверки на робота.
- Не считать снимок экрана доказательством разбора: щёлкать надо по
  именам из `browser_snapshot`, а не по координатам.
- Не запускать два моста на одном профиле: профиль открывается одним
  браузером за раз.

## Проверка моста

Признак работающего моста — страница открылась и заголовок прочитан.
Программа делает это кнопкой «Проверить браузер» и сохраняет снимок
экрана; снимок лежит в `cache/browsers/check.png` рядом с настройками.

Если проверка не прошла, в сообщении будет причина словами сервера —
например, «Chromium distribution 'chrome' is not found» значит, что
выбранный браузер не установлен. Так и скажи человеку: не «не работает»,
а что именно не нашлось.
