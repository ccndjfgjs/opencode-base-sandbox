## 0. Что это за задача

Пользователь написал план (приложен отдельным файлом `mcp-bridges-plan.md`, 200 строк): добавить в программу **четыре MCP-моста** (браузеры, OmniRoute, DBHub, LMArena) и **шесть дополнительных инструментов** (rtk, caveman, pxpipe, auto-improve, greenlight, Qwen Code-ревьюер).

Этот файл — **не план**, а ответ на вопрос «что и как внедрять». В нём описан реальный код программы: где какие файлы, какой формат у записей, на что копировать.

**Приоритет требований:**

1. План — что делать (функции, проверки, оговорки).
2. Эта инструкция — как это встраивается в код (файлы, форматы, шаблоны).
3. Существующий код — образец, который нельзя ломать.

Если план и код противоречат друг другу — не выбирай молча, напиши в описании PR, где разошлись.

**Точка отсчёта:** `python tools\dbapp\selftest.py` даёт **1382/1382, exit 0**. Это число не должно уменьшаться ни в одном PR.

### Как работать (жёстко)

- **Один пункт плана = один PR.** Не смешивай: DBHub в один PR, браузерный мост — в другой.
- Порядок строго из плана: DBHub → браузеры → OmniRoute → LMArena → rtk+caveman → pxpipe → auto-improve → greenlight → Qwen Code.
- **Не начинай следующий пункт, пока не закрыт предыдущий.** После каждого пункта — прогон самопроверки, коммит, PR, и ждёшь.
- Коммит делай на ветке с понятным именем, PR открывай сразу.
- Коммиты и описания PR — по-русски, коротко, без воды.
- **Ничего не придумывай про внешние инструменты.** Порядок установки, команды, флаги и адреса берутся из README того репозитория, которое названо в плане. Не из памяти, не «по аналогии». Если не нашёл — так и напиши в описании PR, что именно не удалось выяснить.
- Всё, что зависит от конкретной машины, проверяется честно: нет проверки — так и пиши «не проверено», зелёную отметку не ставь.

## 2. Из чего состоит мост (шесть деталей, все обязательны)

Мост в этом проекте — это не модуль, а набор из шести частей. Если нет хотя бы одной — мост не работает.

1. **Код моста** → `tools\thirdparty\<имя>\` со своим окружением (`.venv` или `package.json`).
2. **Лаунчер** → `tools\dbapp\launchers\<имя>_bridge_launcher.py`. Единственное место, где секрет попадает в окружение процесса.
3. **Запись в реестре** → `данные\mcp-registry.json`, в массив `servers[]`.
4. **Живая проверка** → функция уровня модуля: «не порт слушается, а протокол отвечает».
5. **Автонастройка** → `auto_setup_*(dest, server, progress=None) -> (messages, errors)`.
6. **Кнопка** → добавить id в `AUTO_SERVERS` (`main.py:2657`) и ветку в `_reg_auto()` (`main.py:2899–2950`).

Плюс, если нужен скилл агента: папка в `skills\` + запись в `данные\skills-index.json` + строка в `skills\_ОПИСАНИЕ-НАВНЫКОВ.md`.

## 3. Формат записи в реестре

Файл `данные\mcp-registry.json`, `schema: "opencode-base-mcp-registry-v1"`. Формат записи `ensure_ascii=False, indent=2` — сохраняй его, иначе diff будет весь файл.

### Обязательные поля

```json
{
  "id": "dbhub",
  "name": "DBHub (PostgreSQL, MySQL, SQLite, SQL Server)",
  "source": "https://github.com/bytebase/dbhub",
  "install": "Коротко для человека: как ставится.",
  "program_install": {
    "method": "none",
    "official_url": "https://github.com/bytebase/dbhub",
    "instructions": "Запускается через npx, отдельно ставить нечего.",
    "bridge": "bundled",
    "checked": "07.10.2026",
    "known_good": [],
    "bridge_checked": false
  },
  "connection": {
    "kind": "local",
    "command": ["{DBAPP_PYTHON}", "{PROGRAM}/tools/dbapp/launchers/dbhub_bridge_launcher.py"],
    "warm_up": false,
    "note": "Пароль от базы в конфиг opencode не попадает: лежит рядом с настройками, лаунчер передаёт через переменную окружения."
  },
  "license": "MIT",
  "tools_count": 20,
  "why": "Один сервер вместо отдельных на каждую базу данных.",
  "requires": [
    {
      "what": "Node.js 18+",
      "type": "command",
      "check": "node",
      "args": ["--version"],
      "min_version": 18,
      "max_version": 0,
      "until": "",
      "blocks": false,
      "note": "npx качает сервер сам."
    }
  ],
  "ready_here": true,
  "verdict": "Работает: установка через npx, пароль не пишется в конфиг opencode."
}
```

### Правила по полям

- **`id`** — ключ. Имя блока в `mcp.jsonc`. Только же, что в `AUTO_SERVERS`, если нужна автонастройка.
- **`name`** — что видит человек в таблице. Содержательно, с версией-диапазоном, если есть.
- **`source`** — URL, по кнопке «Открыть источник». Проверь, что ссылка живая.
- **`install`** — текст для человека. **Машинно не читается.** Поэтому рядом обязательно `program_install`.
- **`program_install.method`** — строго одно из: `winget`, `official-download`, `manual`, `none`. Неизвестное значение = кнопка установки пропадает, карточка скажет «вручную».
- **`program_install.bridge`** — `""` или `"bundled"`. `bundled` = «мост лежит внутри программы».
- **`connection.command`** — **обязательно плейсхолдеры**, не настоящие пути: `{DBAPP_PYTHON}` и `{PROGRAM}`. Настоящие пути подставит `mcp_registry.resolve_command()`. Абсолютный путь в реестре едет в публичный репозиторий — это ошибка.
- **`connection.kind`** — `local` (команда) или `remote` (url). Нужен хотя бы один из трёх ключей: `command`, `url`, `manual_config`. **Пустой `connection` = сервер нечем включать, самопроверка упадёт.**
- **`connection.warm_up`** — `true` только если сервер тяжёлый и надо заранее прогреть кэш npx (180 секунд ожидания).
- **`requires[]`** — у каждого элемента **обязательно** поле `type`, одно из: `command`, `program`, `manual`, `plugin`. Без `type` проверка не отработает.
- **`requires[].until` / `max_version`** — верхняя граница совместимости, если она есть. Понимает `263.*`, `263.5701.*`, `18`, `18.0`.
- **`requires[].blocks`** — `true` для ручного требования, без которого сервер бессмыслен: тогда сервер не станет готовым.
- **`setup_steps`** — **ровно 7 пунктов**, если сервер настраивается руками. Проверяется тестом.
- **`ready_here`** — снимок «проверено у нас», не про машину пользователя. Ставь `false`, если не проверял.
- **`program_install.bridge_checked` / `known_good`** — живая проверка моста на конкретной версии. Не заполняй, пока реально не проверил.
- **Секретов в реестре быть не должно.** Ни паролей, ни токенов, ни строк подключения с паролем.
- Если сервер требует купленного/приватного ключа — используй механизм ручной конфигурации: `connection.manual_config: true`, тогда программа попросит вставить блок в окне и сохранит его в `mcp-<id>.json` рядом с настройками.

### Отдельно: программы, нужные мостам, но не являющиеся серверами

Если твоему мосту нужна программа (Node.js, Go, Rust), и она уже не описана — добавляй в корневой массив `bridge_requirements.items`, поля: `program`, `method`, `winget_id`, `official_url`, `instructions`, **`required_by`** (массив id серверов).

Внимание: `programs.py::bridge_needs()` собирает карточку из этих полей **вручную**, списком из 12 имён. Если добавишь новое поле — правь и там.

## 4. Лаунчер: шаблон (три существующих — образец)

Смотри `tools\dbapp\launchers\obs_bridge_launcher.py`, `android_bridge_launcher.py`, `ldplayer_bridge_launcher.py`.

**Правила, нарушение которых ломает мост:**

```python
HERE = Path(__file__).resolve().parent
SERVER_DIR = HERE.parent.parent / "thirdparty" / "<имя>"

def say(text: str) -> None:
    """Всё это в stderr. stdout — это протокол MCP."""
    print(text, file=sys.stderr, flush=True)
```

1. **Только stderr.** `print(..., file=sys.stderr, flush=True)`. Если написать в stdout — протокол MCP сломается, и это проверяется тестом.
2. **Без Qt и без импортов программы.** Файл должен запускаться сам по себе.
3. Проверить наличие точки входа, при отсутствии — внятное сообщение в stderr и `return 1`.
4. `env = dict(os.environ)`, дальше точечные правки. **Секрет — только через переменную окружения**, не через аргумент командной строки.
5. Запуск: `subprocess.Popen(argv, cwd=str(SERVER_DIR), env=env, stdin=sys.stdin, stdout=sys.stdout, stderr=sys.stderr)`. Stdio пробрасывается как есть.
6. `try: return proc.wait() except KeyboardInterrupt: proc.terminate(); return 0`.
7. `def main() -> int` и `if __name__ == "__main__": sys.exit(main())`.

**Зачем лаунчер вообще нужен:** пароль обязан попасть в окружение процесса **до** старта. Отсюда же — второй повод: мост может звать внешнюю программу по имени, а её нет в `PATH` (как `adb` у эмулятора). Тогда лаунчер дописывает нужную папку в `PATH` или `PYTHONPATH`.

## 5. Живая проверка и порядок действий

**Главное правило: сначала живая проверка, потом запись в конфиг. Никогда наоборот.**

Живая проверка — это «не порт слушается, а протокол отвечает»:

- OBS: полный handshake v5, с вычислением challenge/secret (`bridges.probe_obs`).
- Android Studio: `initialize` в поток `/stream`, построчно (`android_studio.probe`).
- Эмулятор: `adb shell getprop` — непустой ответ.

Общий шаблон автонастройки (`bridges._finish()` вызывается только после успеха):

```
найти программу → починить её настройки (только при закрытой программе!) →
живая проверка связи → и только потом вписать сервер в opencode.jsonc
```

При неудаче: сообщение с причиной + фраза «в настройки opencode ничего не вписано» — и **выход без записи**. Иначе в списке появится неработающий сервер, и это хуже, чем ничего.

**Правило закрытой программы.** Если пишешь настройки чужой программы (OBS, Android Studio, эмулятор) — проверь `tasklist`, и если она запущена, скажи: «Закрой и нажми кнопку ещё раз». Отсюда в `setup_steps` и берётся требование нажимать кнопку дважды.

### Идемпотентность — не трогай, но знай

`enable()` (`mcp_registry.py:1042–1063`) сравнивает **смысл** блока, а не байты. Если блок уже записан и смысл тот же — файл **не перезаписывается**, выводится «уже записан в настройки — файл не трогаю, opencode не перезапускаю».

Причина в коде: opencode перезапускает все MCP-серверы на каждое изменение файла. Лишняя запись = новый экземпляр моста.

**Не обходи этот механизм.** Если твоя запись кажется «не такой» — сначала проверь `build_block()` (`mcp_registry.py:848–880`) и `insert_entry()` (`opencode_caps.py:338–388`), а потом уже правь. Тест на идемпотентность: два `enable()` подряд → файл побайтово тот же, `count('"obs"') == 1`.

## 7. Инструменты, которые не MCP

rtk, caveman, pxpipe, auto-improve, greenlight, Qwen Code — это **не** MCP-серверы. Их в `mcp-registry.json` **не добавляют**.

Куда что:

| Инструмент | Куда | Комментарий |
| --- | --- | --- |
| rtk | `tools\thirdparty\rtk\` + подключение в `config\opencode.jsonc` или `config\AGENTS.md` | Бинарник. Переключатель вкл/выкл — на вкладке opencode |
| caveman | `config\AGENTS.md` или папка скилла | Сначала проверь в README, поддерживается ли opencode |
| pxpipe | настройка подключения + переключатель | Прокси, по умолчанию выключен |
| auto-improve | `tools\thirdparty\auto-improve\` или скилл | Python-скрипт, ключ вне репозитория |
| greenlight | `tools\thirdparty\greenlight\` + скилл | Консольная программа, только для iOS |
| Qwen Code | папка скилла + импорт агента | Консольный агент, не сервер |

**Переключатели вкл/выкл** делаются на вкладке opencode (класс `CapsTab` в `main.py`). Найди в коде, как там устроены существующие переключатели, и сделай так же — новый вид виджетов не вводи.

**Правила подключения внешних инструментов** уже есть в `config\AGENTS.md` (раздел «Скиллы и агенты — выбирать до работы»). Новый инструмент упоминается там же, где перечислены остальные, — коротко, одной строкой.

## 8. Секреты

`.gitignore` репозитория уже закрывает секреты **этой** машины: `config/.secrets/`, `config/cache/`, `config/device_id`, `config/hwid`, `config/data/`, `config/preferences.json`.

Для новых секретов (пароль от базы, токены провайдеров OmniRoute, токен арены, ключ модели-судья) следуй тому же принципу — **по образцу уже закрытого, с комментарием-обоснованием над блоком**, что именно утекает и почему.

| Что | Где лежит |
| --- | --- |
| Пароль (как у OBS) | `<папка настроек>\mcp-*-password.txt` — **рядом с настройками, не в репозитории** |

- **Никогда** в `opencode.jsonc`, в реестре, в логах, в сообщениях окна.
- В чат и в логи токены не выводить. Ни при какой отладке.
- Передача — только через переменную окружения в лаунчере.

## 9. Самопроверка

```cmd
python tools\dbapp\selftest.py
```

Нужен тот Python, где стоит **PyQt6** (не системный). Сейчас: **1382 проверок пройдено, exit 0**. Число не должно уменьшаться. Каждая новая возможность должна добавить свои проверки.

Три функции:

- `check(хорошо, текст)` — обычная проверка.
- `check_machine(хорошо, текст)` — зависит от машины. Состояние «НЕ ПРОВЕРЕНО» не входит ни в провалы, ни в число выполненных.
- Итог считается сам, руками ничего править не надо.

**Куда добавлять проверки нового моста:**

| Что проверяем | Секция selftest.py |
| --- | --- |
| Запись реестра целиком, типы требований, `build_block()` | «5д. Реестр серверов MCP» (~стр. 423–700) |
| Лаунчер на месте, пишет в stderr, секрет через env | «23. OBS и эмуляторы» (~4003–4081) |

| Идемпотентность записи | там же (~4631–4737) |
| Границы версий и `program_install` | «8л. Границы версий и блок program_install» |
| Кнопки карточек | «8о. Карточки и кнопки» |
| Скиллы и индекс | «5а. Скиллы, индекс и реестр» |

**Обязательно проверь в каждом PR:**

- запись реестра проходит все проверки формата;
- лаунчер на месте и `file=sys.stderr` есть в исходнике;
- `{PROGRAM}` записан плейсхолдером, настоящие пути не вписаны;
- если новый скилл — папка ↔ индекс совпадают один в один, все `when`/`trigger`/`result` непустые, `---` ограждения есть;
- если затронут `selftest.py` — прогон зелёный, число не упало.

**Проверка синхронизации скиллов:** `python tools\dbapp\check_skills_sync.py`. Коды: `0` — совпадают, `1` — расхождения, **`3` — сверка не настроена** (в песочнице это норма, не ошибка).

**Синтаксис:** Python — `python -m py_compile <файл>`, JavaScript — `node --check <файл>`.

## 10. Рецепт по каждому пункту

### 1. DBHub (начинай с него)

- Запись в `servers[]`: `id: "dbhub"`, `connection.kind: "local"`, команда через `{DBAPP_PYTHON}` + лаунчер.
- `tools\dbapp\launchers\dbhub_bridge_launcher.py` по шаблону §4. Как передать конфиг и пароль — выясни из README DBHub, не придумывай.
- Форма подключения: рядом с существующими окнами (`ObsPasswordDialog`, `ManualConfigDialog` в `main.py`) сделай свою. Тип БД, DSN, имя источника.
- `dbhub.toml` с секциями `[[sources]]` — пишется рядом с настройками, **режим «только чтение» по умолчанию**, лимит строк в ответе задаётся.
- `requires`: Node.js. Проверить, что `npx` действительно качает сервер, и отразить это в `warm_up`.
- Живая проверка: реальное соединение с источником, а не «порт открыт».
- Кнопки: включить, выключить, добавить подключение, проверить соединение.

### 2. Браузерный мост (Playwright MCP)

- Запись в `servers[]`, `id: "playwright-browser"`, запуск через `npx` по README `@playwright/mcp`.
- Выбор браузера в окне: Chrome, Edge, Яндекс.Браузер, Firefox.
- Chrome/Edge — штатный флаг Playwright. **Сверь точное имя и значения флагов по README**, не по памяти.
- Яндекс.Браузер — Chromium: запуск по пути к исполняемому файлу либо подключение по CDP с портом отладки.
- **Firefox — пункт с честностью.** Playwright поддерживает только свою сборку Firefox, а к обычному установленному по CDP не подключиться. Проверь по актуальной версии и, если ограничение настоящее, покажи его пользователю прямо в окне. Не выдумывай обход и не пиши «поддерживается».
- **Отдельный профиль** браузера для нейросети, чтобы она не видела личные вкладки. Режим «мой браузер с моими сессиями» — только явный выбор пользователя.
- Живая проверка: открыть страницу и прочитать заголовок, а не только дождаться порта.

### 3. OmniRoute

- Код в `tools\thirdparty\omniroute\`, запуск через лаунчер по шаблону §4.
- **Порядок установки, команду запуска и адрес API берёшь из README репозитория `diegosouzapw`.** Не из памяти.
- Живая проверка: настоящий запрос к API OmniRoute.
- Кнопки: развернуть, запустить, перезапустить, показать статус.
- Провайдеры добавляются в opencode **через существующий механизм** в `opencode_caps.py` (там `PROVIDER_PRESETS` и слияние с `mcp`/`permission`). Не дописывай текстом в `opencode.jsonc` руками.
- Скилл `skills\omniroute\SKILL.md` + запись в индекс + описание. Скилл умеет: подключаться после запуска, добавлять бесплатных провайдеров при каждом развёртывании и перезапуске, перезапускать мост при падении.

### 3а. Мост LMArena

- Всё как у OmniRoute: код в `tools\thirdparty\`, лаунчер, живая проверка ответом модели, кнопки, скилл.
- **Форк выбирай сам и обоснуй:** `CloudWaddie/LMArenaBridge`, `lianues/lmarenabridge`, `hung319/larena2api` — смотри дату последнего коммита, README, открытые проблемы. В описании PR напиши, почему выбран этот.
- Способ авторизации — из README форка. Ничего не придумывай.
- **Обязательные предупреждения в окне до первого запуска:** работа через веб-сервис Arena, а не через официальный API; возможное несоответствие условиям сервиса; запросы уходят в Arena и могут использоваться для оценки — приватный код и секреты отправлять нельзя; стелс-модели экспериментальны и список меняется; бесплатный доступ ограничен лимитами и защитой от роботов.
- **По умолчанию выключен**, включается только после явного согласия.
- Токен — рядом с настройками, в `.gitignore`, в логи и чат не выводить.
- Если токен протух или сервис молчит — окно говорит об этом прямо, **без зелёной отметки**.

### 4. rtk и caveman

- rtk: `tools\thirdparty\rtk\`, установка по README. Подключение так, чтобы вывод команд шёл через него. Переключатель на вкладке opencode.
- Проверка: длинная команда даёт заметно более короткий вывод. Замерь и покажи числа.
- caveman: сначала проверь в README, поддерживается ли opencode. Если нет — перенеси правила в `config\AGENTS.md` вручную. Уровни «лёгкий / полный» — переключатель.
- Экономию 65–75% **не пиши как факт** — это заявление автора, пометь так и в описании, и в скилле.

### 5. pxpipe

- Запуск по README, адрес по умолчанию — как в плане. Переключатель **по умолчанию выключен**.
- Оговорку про модели, плохо различающие символы при расшифровке, покажи пользователю до включения.
- Проверка: обычная задача проходит через прокси без ошибок.

### 6. auto-improve

- Это **не** MCP и **не** экономия токенов. Кладётся в `tools\thirdparty\` или оформляется скиллом с записью в индекс.
- Установку, ключи запуска и настройку модели-судьи берёшь из README.
- **Запуск только в отдельной git-ветке** — скрипт сам делает коммиты и откаты. Об этом должно быть сказано в скилле прямым текстом.
- Ключ модели-судьи — вне репозитория, в `.gitignore`.

### 7. greenlight

- Только для iOS-приложений. По умолчанию выключено. Для opencode-base (PyQt6, Windows) не нужен — так и напиши в описании опции.
- Установку берёшь из README. На Windows выбирай `go install` или сборку из исходников; Homebrew не подходит. **Проверь, что Go и make вообще установлены**, и если нет — скажи об этом прямо, а не молча.
- Основной сканер работает офлайн и наружу ничего не отправляет.
- `greenlight verify` идёт через сторонний облачный сервис — **только по явному подтверждению пользователя**, с предупреждением.

### 8. Qwen Code-ревьюер

- Установку и ключи запуска берёшь из README `QwenLM/qwen-code` и официальной документации.
- Встраивается **через существующий механизм импорта агентов** — найди его в коде сам (поищи, где программа добавляет импортируемых агентов) и сделай так же, как сделаны уже встроенные.
- Выбор модели ревьюера — из провайдеров, уже подключённых в opencode. Ключ не выводится в чат и логи. **Несовместимый провайдер — честно сказать пользователю, а не подставлять наугад.**
- Режим ревью: скилл берёт `git diff`, запускает Qwen Code в headless-режиме **без права править файлы**, замечания возвращает основному агенту. Ревьюер код не меняет.
- Режим «спор» — отдельный переключатель, по умолчанию **выключен**: раунды с лимитом (по умолчанию 3), при исчерпании лимита — развилка пользователю, а не решение скилла. У каждого раунда виден расход токенов.
- Оговорки (покажи в описании PR): ревью не экономит токены; код из `git diff` уходит выбранному провайдеру; две модели могут ошибаться обе, спор не доказывает правоту; ревьюера лучше брать другой моделью, чем у основного агента.

## 11. Что нельзя делать

- **Пути настоящие вместо пометок.** Только `{{BASE}}`, `{{DESKTOP}}` и подобные.
- **Пароли и токены** — куда угодно, кроме файла рядом с настройками.
- **Повторная запись настроек.** Механизм идемпотентности не обходить.
- **Зелёная отметка без живой проверки.** Нет живой программы — окно говорит об этом прямо.
- **Пустой `connection`** у записи реестра.
- **`setup_steps` не из 7 пунктов**, если сервер настраивается руками.
- **Папка скилла без записи в индексе** или наоборот.
- **Инструмент, который не MCP, добавленный в реестр MCP.**
- **Действия с чужими файлами настроек.** Программа только добавляет своё или убирает своё.
- **Папки пользователя.** Не удалять, не перемещать, не трогать папки проектов и копии.
- **Служебные папки пакетов.** Не писать в `npm`, `node_modules`.
- **Права администратора.** Программа сама их не берёт, и добавленный тобой код тоже не должен.
- **Придуманные флаги и команды.** Неизвестно — пиши «не выяснил» в описании PR.

## 12. Определение готовности пункта
